## 1. 定位（Owen 定）

- **B：日常拼屏观影，佐餐场景**，单次播放约 30 分钟量级。
- 设备：**任意多台**，跨品牌跨系统；**一期安卓 + 鸿蒙先行，iOS 排除**（协议预留，后续再议）。形态含手机、折叠屏、平板。
- 摆放：**随意摆放拼凑**，不要求规整网格；位置识别以**编号定位**为准（Owen 裁：拍照后让程序自动组织太抽象，编号定位靠谱）。
- 视频来源：**各视频平台的分享链接**。
- 核心荷载（由定位推出）：长时同步不漂移 > 起播仪式感；几何标定必须支持任意摆放；发现/组会必须跨品牌通用。

## 2. 同步子系统（核心）

目标：任意两台之间进度偏差，稳态 ≤50ms，瞬时上限 120ms（超限触发硬校正）。

1. **组会**：主机建会，屏幕显示二维码；从机扫码入会（同 WiFi）。无路由器场景降级：从机连主机热点（iOS 需用户手动开热点，应用只做引导）。
2. **对时**：从机与主机做多次往返测时（类 NTP），估计时钟偏差与网络延迟，目标对时误差 ≤10ms。
3. **分发与预加载**：主机把解析后的媒体直链发给各从机；各机自拉流并预缓冲到可播状态后回报 READY；全员 READY 才允许起播。
4. **定时起播**：主机下发未来时刻 T0（按对时后的统一时钟），各机在 T0 同时起播。不使用「收到命令即播」。
5. **播中校正**（30 分钟荷载的关键）：
   - 主机每 5 秒广播自身进度（媒体时间 + 主机时钟）。
   - 从机偏差 ≤50ms：不动；50–120ms：微调播放速率（0.97–1.03）无感追赶；>120ms：直接 seek 硬校正（画面会跳一下，可接受，佐餐场景不敏感）。
   - 从机卡顿再缓冲后，按当前主机进度 seek 归队，不从原地续播。
6. **音频**：只允许一台出声——默认主机，可在界面指定任意一台为音频机；其余静音。此约束写死，不提供「多台齐放」选项（回声不可解）。

## 3. 位置识别与几何标定（编号定位，Owen 裁定）

### 3.1 主方案：编号定位

1. 入会即编号：每台从机入会时领到唯一编号，全屏常显大号数字（播放前也可一键闪号核对）。
2. 主机布局图上是同号的设备块，用户**按编号把设备块拖到与实物一致的位置**（可自由拖放、可旋转角度、可缩放表示大小），任意摆放就在布局图里如实复刻——位置由人确认，不由程序猜。
3. 主机按布局下发每台的取景参数：每台渲染整体画面的对应子区域；布局中的相对角度差用透视/旋转变换近似校正。
4. 对位核对：布局完成后全体闪号一次，用户目测布局图与实物逐号对应，错了拖正即可。标定存档，同组设备下次免重排（摆放变了重排一次）。

### 3.2 非 v1：拍照自动标定

拍照检出编号与四边形、由程序自动组织布局——Owen 评「有点抽象」，v1 不做；后续若做，也只作辅助（自动排好后仍由用户按编号确认），不替代编号定位。

### 3.3 取景模型（与上一轮结论一致）

- **不切片分发**：每台播同一份完整视频，只渲染自己的取景窗（GPU 裁剪 + 透视变换）。
- **边框补偿**：编号布局中每个设备块按实物外形尺寸（含边框）复刻摆放，块与块之间的间隔即边框造成的画面断开带，取景时按布局几何自然扣除；用户可对单台做像素级微调。
- 折叠屏展开态、平板的大屏都只是「一块更大的四边形」，同一模型处理。

## 4. 分享链接解析子系统（真实难点，单列）

- 分享链接 ≠ 媒体地址。各平台需逐个适配解析：短链展开 → 作品 ID → 取流地址（清晰度可选）。
- 已知硬点（与自研抖音下载脚本同一堵墙）：抖音等平台接口有签名校验（如 a_bogus），裸接口调用会被拒；可行路径是借已登录会话的页面上下文取数，或用平台公开分享页的嵌套数据。解析成功率随平台改版波动，属持续维护项。
- 流地址多为**签名限时**：必须在建会时现解析现用，解析结果只在会话内分发，不缓存复用。
- 分期口径（Owen 裁定）：一期解析只做**抖音 + B站**两个平台；同时保留两个兜底入口——直接粘贴 mp4/m3u8 直链、选本地文件由主机在局域网内分发。
- 合规边界：仅播放用户自己提供的链接，不提供任何平台内容搜索/推荐/下载存档功能。

## 5. 平台与实现分工

- 播放器各端原生：一期**安卓 = Media3/ExoPlayer**（小米、三星共用）、**鸿蒙 NEXT = ArkTS + AVPlayer**（独立一套）；iOS 不在一期范围内。
- 统一的是**会话协议**（组会/对时/进度广播/布局下发），用 WebSocket + JSON，各端实现同一份协议文档；iOS 将来若加入，照协议实现即可。协议先行，播放器跟上。
- 建议顺序：先单安卓把同步内核（对时/起播/校正）验到数值达标，再铺鸿蒙端——两端播放器行为差异是同步精度的最大变量，内核先行可隔离问题。

## 6. 非目标（v1 明确不做，CC-002 式单列）

- 不做在线影视库/搜索/推荐；不做下载存档；不做跨公网组会（只局域网）；不做商用广告机远程管理；不做多台同时出声。

## 7. 验收标准（量尺草案）

- 4 台混合设备（安卓 + 鸿蒙至少各 1 台）随意摆放，编号定位一次排定，缝对位误差在观众位目测无错位。
- 30 分钟连续播放，任意时刻抽查两台进度差 ≤120ms；人为暂停/卡顿一台后能自动归队。
- 分享链接（抖音、B站各选 3 条）建会到起播全流程 ≤60 秒。

## 附则：布局三原则（Owen 2026-11-12 定，验收口径）

1. **不变形是基础**：任何模式、任何重排下渲染必须等比，不许拉伸。此为不可让渡的底线（v0.3 起达标）。
2. **不缺画面、不漏信息是进阶**：完整显示（黑边条＋整幅放下，含横向与竖向旋转两式）才算达成；铺满裁切只满屏、不算完整。
3. **加从机、减从机，排布跟随变更**：成员变化（入场、退出、掉线）时布局按活跃成员自动重排，画面随之补齐或重新划分，播放不中断。

显示模式三档（v0.6.1）：cover 铺满裁切 / contain_h 完整·横向 / contain_v 完整·竖向（仅单台全屏）。
